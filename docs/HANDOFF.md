## Что изменено

- Поставки используют исходные SupplyForm, HistoryView, StatsView, фильтры, графики и экспорт ПОСТАВКИВСРФ, встроенные в армейскую оболочку. Есть РЛС/ВС/ОБ-7, получатель, организации, машины, сопровождение, московское время, подтверждение, черновик, повтор, история, редактирование и статистика. Вместо Firebase — PostgreSQL API. Проверки количества машин, конфликт версии, идемпотентное создание, мягкое удаление и история изменений выполняются на сервере.
- Состав использует свободную матрицу ЦГБ: пустые ячейки, перемещение карточек, индивидуальное число колонок в строке, категории, фото и экспорт. ВП и премирование получают сотрудников из этого состава; нужны ФИО и статик.
- Перенесён подробный интерфейс результатов экзамена ЦГБ. Правильные ответы и расчёт результата контролирует сервер. Лимит попыток привязан к выданному аккаунту. Ручная подмена баллов не поддерживается.
- Приёмная, учебные материалы и лекции доступны по прямым ссылкам и скрыты из навигации. Контакты лидера находятся в README.
- Удалены действующие модули Discord-бота, чтение участников и каналов, выбор ролей из бот-кэша, обработка реакций, импорт заявлений из сообщений и автоматическая статистика налётов. Исторические таблицы остаются в миграциях, но закрыты API даже администратору.
- Девять маршрутов вебхуков с шифрованием URL, очередью и отдельным worker. Решения по обращениям принимаются на сайте. Отправка поставки: «История» → карточка → «В Discord».
- Истечение взысканий выполняет worker сайта; повторный запуск не создаёт повторное снятие. Конвертация предупреждений старым ботом удалена.
- Исправлены ошибка запуска страницы ВП, оставшиеся элементы настроек каналов, права навигации заявок и устаревший кэш состава.

## Проверки

42 автоматизированных сценария: серверные права и закрытые данные, отсутствие самоназначения администратора, регистрация и назначение роли проверяющим, экзамены и сброс попыток, жалобы и обязательные поля, поставки, webhook-очередь и обновление сообщения, Origin, приватные файлы, ограниченная PostgreSQL-роль, недоступность таблиц бота, матрица состава, истечение взысканий и исходные расчёты поставок. Проверки используют PostgreSQL-движок PGlite; HTTP Discord подменяется.

Синтаксис JS/inline-скриптов и локальные ссылки проверяются `npm run check`. Зависимости проверены `npm audit`: известных уязвимостей не найдено на дату проверки.

Через браузер проверены вход, создание поставки исходной формой, появление записи в истории и статистике, сохранение настроек жалоб, загрузка ВП и обновление из состава, открытие режима матрицы и настроек колонок. В предыдущем проходе проверены создание и публикация теста, добавление вопроса, сдача с серверным результатом и сохранение карточки сотрудника. Это не означает ручной проверки каждой комбинации действий и прав во всех разделах.

## Условия запуска

- Постоянный PostgreSQL, systemd и HTTPS-прокси на хосте техадминов ещё не запускались. Локальный просмотр использует временную БД: данные исчезают при перезапуске.
- Реальные Discord-вебхуки не настроены, внешние сообщения не отправлялись. Перед рабочим запуском требуется тест каждого используемого маршрута.
- Автоматического чтения Discord-ролей нет. Вебхук только отправляет сообщения; сотрудников и подразделения ведут в составе сайта. Введённый Discord ID не является OAuth-подтверждением личности.
- Учебные примеры и шаблоны доступны для редактирования; действующие игровые регламенты и экзаменационные вопросы публикует командование.
- Премирование отправляет данные текстовым приложением. Автоматическая архивация после отправки не включена; черновик сохраняется. Экспорт изображений остаётся отдельной функцией.
- Маршруты вебхуков разделены по типам событий, а не по каждому отделу. Обжалование из приёмной относится к requests, жалоба на сотрудника — к complaints.
- Часть исходных документов, шрифтов и медиа загружается с внешних адресов. Пользовательские фото хранятся на сервере и требуют резервного копирования.
