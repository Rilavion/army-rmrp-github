# Отчёт о подготовке · 17 октября 2026

## Основа и внешний вид

Использован исходный `army-rmrp-patriki-main (5)/army-rmrp-patriki-main`, а не ранее созданный упрощённый сайт. Главная, фон, темы, анимация, карта, индивидуальные страницы ВП, премирования, заявок и документов сохранены. SHA-256 исходного и подготовленного `style.css` одинаков: `25a5247b377442f79383bebf1f4cdd90ffc59075d429b511a5ef496ab8100ee9`.

Из ЦГБ перенесены редактор состава, редактор и прохождение экзаменов. Поверх исходного CSS используются отдельные стили адаптированных разделов. Исходные проекты не изменялись. Старые папки `army-rmrp-handoff` и `army-rmrp-github-ready` не являются результатом этой версии.

## Изменения

- Собственный API и PostgreSQL вместо прямого доступа браузера к Supabase; серверные права и сессии.
- Экзамены: один/несколько ответов, порядок, изображения вопросов и вариантов, случайная выборка, таймер, лимиты аккаунта, серверные баллы. Сброс с причиной, включая незавершённые запуски; история сохраняется.
- Лекции по КМБ, ВА, поставкам, ВП, ВК и подразделениям, редактор, отметка прочтения, ссылка на экзамен. Добавлены два редактируемых учебных примера экзаменов по работе с порталом и поставкам. Это вводные памятки; действующие игровые регламенты и банк экзаменов публикует командование.
- Приёмная: заявка на службу, подразделение, перевод, допуск, военный билет, инструктор, обучение, обжалование, аудит склада и предложения. Рассмотрение использует существующий раздел заявок.
- Поставки: запрос, редактирование, число выехавших/прибывших машин, процент доставки, ручная отправка и обновление сообщения Discord.
- Девять маршрутов вебхуков, шифрование секретов, очередь и обработка ошибок; без Discord-бота.
- Подготовлены шаблоны жалобы и служебных отчётов, контакты лидера и разработчика в README, документация, миграции и примеры служб.
- JS разложен по `public/js/core`, `features`, `ui`, `utils`; исходный CSS сохранён.

## Исправления по последней обратной связи

- Новый журнал РЛС/ВС/ОБ-7: десять организаций, получатель, машины, сопровождение, московские даты, сводка, фильтры, постраничная история, черновик, повтор, CSV/JSON, PNG сводки. PostgreSQL вместо облачной БД отдельного проекта.
- Серверные итоги, проверка количества машин, конфликт версии, идемпотентное создание, мягкое удаление и восстановление администратором, снимки истории. Две новые SQL-таблицы; справочник содержит 71 таблицу.
- Состав из ЦГБ: категории, строки и колонки, кадрирование фото, экспорт отдела. Проверены добавление категории и сохранение сотрудника через браузер.
- Учебные материалы, лекции и приёмная скрыты в навигации; прямые ссылки работают. Блок связи с лидером удалён со страницы информации. README адаптирован по структуре образца: контакты и 17 разделов.
- Убраны задержки переходов и повторные анимации карточек; фоновая анимация по умолчанию выключена. Эмблема шапки хранится локально. Подписки не вызывают обновление при неизменных данных.
- ВП и премирование получают сотрудников из состава сайта. Отправка архива ВП больше не требует канал от отсутствующего бота.

## Проверено

18 автоматизированных сценариев проходят на PostgreSQL-движке PGlite: права, закрытые данные, отсутствие самоназначения администратора, экзамены, сброс попыток, жалобы, обязательные поля, поставки, обновление одного webhook-сообщения, Origin, приватные файлы и ограниченная PostgreSQL-роль. Проверены синтаксис JS/inline-скриптов и локальные ссылки.

В браузере проверены исходная главная, вход администратора, лекции, создание и публикация теста, добавление вопроса и сдача с серверным результатом 100%. Остальные сохранённые разделы не объявляются полностью вручную протестированными только на основании наличия страниц.

## Условия передачи

- Постоянный PostgreSQL-сервер, systemd и HTTPS-прокси на хосте техадминов ещё не запускались. Локальная демонстрация использует временную БД, её данные исчезают при перезапуске.
- Реальные Discord-вебхуки не настроены и внешние сообщения не отправлялись; доставка проверена с подменённым HTTP-ответом. Перед рабочим запуском нужен один реальный тест каждого используемого маршрута.
- Автоматическое чтение Discord-ролей для ВП/премирования отложено по просьбе заказчика. ВП и премирование получают сотрудников из состава сайта через защищённый справочник. ФИО и статик обязательны; ключ проверки — static:000-000. Это не чтение Discord-ролей.
- Премирование отправляет данные текстовым приложением; автоматическая архивация после Discord-публикации не включена, черновик сохраняется. Экспорт изображений исходного сайта остаётся отдельной функцией.
- Вебхуки маршрутизируются по типам событий, не по каждому отделу. Обжалование из приёмной идёт в общий маршрут requests; жалоба на сотрудника — complaints.
- Публичные лекции не являются подтверждением личности. Экзамен требует выданного аккаунта; Discord-ник и статик вводятся пользователем, это не OAuth-подтверждение.
- Некоторые изображения, видео, документы и шрифты исходного сайта остаются внешними ссылками. Их доступность зависит от источника. Собственные загружаемые фото хранятся на сервере.

Загружать следует содержимое `army-rmrp-github-ready-original`. В пакет не входят локальные пароли, тестовые БД, node_modules, старые архивы и секретные URL.
