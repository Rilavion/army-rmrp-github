# Discord: необходимые вебхуки

Создать вебхук в настройках соответствующего текстового канала Discord. Войти администратором сайта → «Уведомления Discord» → вставить URL → включить маршрут. Один маршрут соответствует одному вебхуку; несколько маршрутов можно направить в один канал. URL — секрет, его нельзя публиковать в репозитории или клиентском config.js.

| Маршрут | Рекомендуемый канал | Назначение |
|---|---|---|
| `supply_requests` | запрос-поставок | Новый запрос поставки |
| `supplies` | отчет-поставок | Отчёт с числом выехавших/прибывших машин и процентом доставки |
| `requests` | отчеты-электронных-заявок или документооборот | Рапорты, отпуска, восстановление, переводы, допуски и другие обращения |
| `complaints` | подача-жалобы-на-военнослужащего | Уведомления по жалобам и их рассмотрению |
| `exams` | отчёты-экзаменов | Серверные результаты экзаменов |
| `reports` | еженедельные-отчёты | Служебные отчёты |
| `payroll` | еженедельные-премии | Приказы премирования; данные приложены текстовым файлом |
| `vp` | отчётность-задержаний / закрытый канал ВП | Архивный отчёт ВП |
| `warehouse` | аудит-склада | Новое обращение по аудиту склада |

Для начала достаточно `supply_requests`, `supplies`, `requests`, `exams`. Остальные подключаются при использовании соответствующих модулей. Каналы с персональными и дисциплинарными данными должны быть доступны только уполномоченным сотрудникам.

Доставка идёт отдельным worker через очередь PostgreSQL. Секрет шифруется AES-256-GCM; API показывает только факт настройки. Разрешён официальный `https://discord.com/api/webhooks/...`, перенаправления запрещены, массовые упоминания отключены.

Поставки отправляются вручную ответственной ролью. После отправки исправление обновляет то же сообщение по его Discord ID. Состояния очереди: pending, sending, retry, sent, failed, uncertain. При 429 учитывается задержка Discord. Неопределённый результат первого POST не повторяется автоматически, чтобы не создавать дубликаты: техадмин проверяет канал и вручную восстанавливает запись очереди после сверки. Смена вебхука не переносит уже отправленные сообщения в другой канал.

Вебхуки не читают участников, роли, историю канала и реакции и не выдают роли Discord. Автоматическое заполнение ВП/премий по Discord-ролям отложено по просьбе заказчика. Старые ID каналов в настройках исходных модулей не управляют доставкой; маршруты задаются только здесь. Уведомления без бота не предполагают кнопок одобрения в Discord — решение принимается на сайте.
